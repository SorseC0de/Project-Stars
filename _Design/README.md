# Design

The decisions behind Project Stars, in the user's words rather than the code's.

These live here rather than in an assistant's memory so they are **versioned,
diffable, and openable in Xcode next to what they describe**. A design document
nobody can find is a design document that gets contradicted.

## What is here

| Document | What it settles |
|---|---|
| `project-stars-goal` | Survival is the win condition; damaging tiles is a cost, never a reward. |
| `project-stars-vocabulary` | Pentacle, Z-Action, Nexys, Astra/Terra, Zodea — the design's own names. |
| `project-stars-kit-descriptors` | Complex / Steady / Chance / Tenacious / Mover, and which signs take which. |
| `project-stars-ds-layout` | The top square is display; every control lives in the bottom half. |
| `vagueness-is-deliberate` | Under-explained effect text is the design, not a gap. |
| `forced-risk-should-not-be-punished` | The board must not require a risk and then charge for taking it. |
| `zodiaction-charge-balance` | Why there is no manual charge. |
| `palette-swaps-are-ramp-mappings` | Swaps are ramp mappings, not colour picks. |

## Keeping them true

A rework document describes the **intended** design, which is not always what is
built yet. Where the two disagree, the document is the target and the code is
the progress — say so in the document rather than quietly editing it to match.
